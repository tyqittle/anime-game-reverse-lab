# 《明日方舟》Windows PC 离线单机工程 — 阶段 0 可行性评估

- 评估日期：2026-10-23
- 目标：**《明日方舟》本体（原版塔防）**，在 Windows 本机脱离官方服务器运行；保留干员、地图、技能、战斗，最终以本地存档替代云端依赖
- 阶段状态：**部分可行，但原版完整单机化尚未证实；不能认定已经完成**
- 官方运营状态：**仍在运营，不是停服游戏**。官方 2026-10-16 更新公告：https://ak.hypergryph.com/news/3020
- **目前没有用户提供的 APK / PC 客户端目录，也没有二进制测试样本**。因此“解析到服务器 IP、证实协议、验证离线登录”均为 **未评估**，不编造。

## Windows 当前能做的工作（明确区分产品）

**A. 现有可玩衍生模式**（非原版）：Windows 下有 Git 和 Node 22+ 时，双击 `scripts/start-arknights-solo.cmd`。第一次会拉取固定版的 Stronghold-Protocol、安装 npm 依赖，然后仅监听 `127.0.0.1:3000`。默认不下载版权素材，缺图/模型/音效是预期风险；选择 `-AllowAssetDownloads` 才让上游执行约 720MB 首次素材下载，不会上传到主仓库。不能把这个模式当作原版《明日方舟》已完成离线化。

**B. 原版客户端研究**（待真实样本）：保留原 APK 不变，使用已有 `erlab-apk` 工具生成只读 ZIP/DEX 文件线索与 SHA-256 报告：

```powershell
python -m pip install -e .
erlab-apk "C:\your-personal\Arknights.apk" --out reports/arknights-phase0.json --markdown reports/arknights-phase0.md
```

它只标记文件头/字符串线索，不接触官方服务器、不改 APK，也不能验证协议兼容性。若使用 PC 原生客户端，可先运行 `erlab scan` 获取本地资源清单，再制定对应的 Unity 资源分析流程。

## 实际目标与里程碑（以验收而非 UI 截图作准）

- **阶段 0（当前）**：核验开源项目、版本、许可证、真实能力，建立正确的专用仓库结构；样本分析因缺 APK 保留“未测”。
- **阶段 1**：根据用户合法拥有的同版本 APK / PC 客户端完成只读静态分析（引擎/加固/网络 SDK/本地资源）。
- **阶段 2**：隔离环境中分析本机客户端的实际启动依赖，标注协议对应证据；不对生产服务做测试或破坏。
- **阶段 3**：在兼容性得到验证后才选用适当上游模块做本地会话与核心玩法重建；不把 Stronghold 同人模式伪称为原版单机。
- **阶段 4**：关卡、干员数据、全流程存档持久化与重启恢复。
- **阶段 5**：Windows 原生启动、断网演示、原版关卡胜利、存档恢复的实测记录与截图。

## 风险与停止条件

2026 年的官方服务仍在线。账号认证、服务端存档和长期维护带来技术与许可风险。若客户端和服务器深度耦合、必要资源不可合法获取或开源实现与版本不兼容，应判定特定目标不可行，而不是写假端点或空壳模拟。只在授权的个人离线环境研究。强制边界：无游戏 APK、官方美术音频、大型资源包、登录凭据或专有密钥的公开上传；不运营对外私服。
