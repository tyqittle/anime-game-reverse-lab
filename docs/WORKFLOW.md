# 通用逆向研究流程

## 统一原则

各游戏只提供配置与证据记录；格式识别、批处理、清单、哈希、报告等公共能力必须落在 `src/erlab/`，**禁止每个游戏复制一份不同的扫描逻辑**。

## 四个阶段

1. **采样**：只使用你获准分析的本地文件，记下游戏版本、样本来源、采集时间和文件大小。原始二进制仅存本机 `samples/`。
2. **盘点**：`erlab scan samples/game-id --out reports/game-id-v1.json`。扩展名不是证据，优先文件头签名；未知格式保持 `unknown`。
3. **分析**：统计包分布、增量更新、重复资源与容器头。针对格式可新增独立解析器模块，并配套小型自制测试夹具。
4. **复现**：记录工具版本、执行命令、输出哈希、验证结果。可公开分享方法、脚本与自行制作的演示样本，不附带任何商业资产。

## 可验证性标记

- `confirmed`：附本地可复现测试、公开依据或已去敏的元数据。
- `tentative`：合理线索但缺验证。
- `unknown`：尚未研究。

## 未来扩展接口

- `src/erlab/parsers/`：签名验证 + 容器元数据解析，解析器接收输入流而非全文件读入。
- `src/erlab/pipelines/`：公共资源处理管线，统一处理预览图、动画依赖和音频映射。
- `games/<id>/`：各游戏仅保存差异配置、来源与调查笔记。
- `viewer/`：以后按版权许可为自有或授权资源实现离线查看器；不直接注入商业游戏运行进程。
