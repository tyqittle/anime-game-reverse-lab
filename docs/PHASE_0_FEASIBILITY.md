## 已实施、可复验的阶段 0 工具

`src/erlab/apk_audit.py` 是零第三方依赖、只读、不联网的 ZIP/DEX 字符串扫描器：计算 SHA-256、引擎文件名线索、网络库关键词、候选 URL **域名**（自动省略路径和密钥）、签名条目提示。它会明确把 SSL Pinning、加密和协议状态标为“unknown”；不能推断游戏可玩、不能判断真服务器是否仍然存在。

```powershell
python -m pip install -e .
erlab-apk "C:\personal\game.apk" --out reports/phase0.json --markdown reports/phase0.md
```

它不改写原 APK，不提取商用资源、不绕过保护、不生成登录补丁，不访问任何服务器。仅有正常的 ZIP 和 DEX 字符串扫描线索。

## 可行性决策和下一阶段

首先确认可获得并合法处理的 APK、引擎和版本，以及是否存在有许可证的**对应游戏**开源实现。之后才评估：资源能否读取、哪些玩法必须向在线服务器询问、协议是否可重实现、本地存档是否能代替账户云存档。遇到服务器强耦合/保护机制/缺失必要资料，可行性应维持“未证实/不可行”，而非宣称已转换成功。

不使用真实线上账户、生产服务器或盗用密钥；如果需要网络行为分析，应限于授权的个人沙箱并脱敏。真实协议未提供时**不应编造 Flask 假服务端**，也不应生成没有目标可供应用的客户端重定向脚本。

## 先交付的真实单机工程

为了让仓库不只是报告，`offline_game/` 已实现**基于真实现成开源 Godot JRPG** 的可重建离线项目，保留原有战斗、人物、对话、地图素材并扩展本地存档与暂停。它不是任何指定停服商业游戏的替代 APK；两条工作流应明确区分。

## 验收门槛

- 工程构建验证：固定上游源码拉取、游戏场景与资产齐全、许可证保留、脚本导入；
- GUI 游戏验证：Godot 实际启动、地图探索、NPC 对话、回合制战斗、重新打开后本地进度恢复；
- 平台发行验证：Windows 二进制 / Android 安装包及兼容设备实测；
- **目标商业游戏**验证：还需该游戏明确的原客户端和合法测试证据。目前全部未测试。

请勿将生成工程等同于已经完成 GUI 全流程或商业 APK 验收。
