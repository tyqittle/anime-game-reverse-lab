# 以公开资料重建游戏系统：可复现方法

这不是“下载官方客户端 = 得到源码”。逆向工程实际是通过**可公开观察的行为**（游戏录像、玩家操作实验、开源示例与公开设计文档）推导规则，再用原创实现重建系统，最后测试偏差。

## 可观测数据 → 机制假设 → 原创实现 → 复验

1. 收集允许使用的视频、游戏截图、官方玩法说明、开发者公开技术分享、取得许可的本地样本；保留 URL/版本/日期/许可证证据。
2. 将系统拆为互相独立的模块：输入、物理、动画、摄像机、攻击判定、敌人决策、场景触发器、可视化、资源管线、存档。不得直接把某厂商 DLL/素材复制进仓库。
3. 为观察结果记录置信度。例如连续两帧位置变化可推算视速度，但录像帧率和游戏的加速度曲线必须纳入误差；不能直接写死“确定 325px/s”。
4. 为每个规则编写行为测试，和可公开重复的截图/输入序列对比；注明哪些是高度还原、哪些是为了可玩性创造的新内容。
5. 使用获许可的素材做资产绑定；无法确认授权则仅保存 SHA-256/文件格式/自制占位资源。
6. 每个目标游戏档案独立归档，不要为某一游戏随意修改所有游戏共同代码。

## 核心模块映射

| 游戏研究对象 | 当前可改动工程 | 验证方式 |
|---|---|---|
| 玩家位移、加速度、二段跳 | `web/js/engine.js` → `updatePlayer` | `node --test tests/test_web_engine.cjs` |
| 敌人寻敌、攻击周期 | `updateEnemies`、`updateBoss` | 定位/伤害/阶段单元测试 |
| 动作和命中框 | `updatePlayer` 中的 `attack`、`hitEnemy` | 不同帧命中判定 |
| 关卡布局、胜利条件 | `web/js/levels.js` | 可离线重新配置 |
| 资源文件外部特征 | `src/erlab/formats.py`, `inventory.py` | Python unittest |
| 合成音效与授权素材替换 | `web/js/audio.js`, `web/js/app.js` | 浏览器交互测试 |

## 与可参考开源项目的关系

参见 [开源项目来源](OPEN_SOURCE_REFERENCES.md)。只有经过许可证核对的代码/素材才能复制；本次 v0.2 未直接复制任何参考仓库源文件，而是独立实现玩法验证原型，避免来源模糊。
